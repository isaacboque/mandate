# UI audit (2026-11-21)

An accessibility and polish audit of the web UI (chat plus contracts panel) after the public-demo changes (header badge, limit card, "Try it in 60 s" tour). Design polish only: no behaviour, wiring or guardrail changed.

**How it was done.** The Hallmark design skill was asked for but could not be installed in the environment that ran this audit (the install was refused by the permission system, so none of its scripts were used and no claim here comes from it). The audit was done by hand against WCAG 2.2 AA:

| Check | How | Result |
| --- | --- | --- |
| Automated WCAG scan | axe-core 4.10.2, tags `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`, `wcag22aa`, `best-practice`, run on 10 states at 1280 px and 380 px: empty chat, draft card, draft form, active contract, proposal, paid receipt, blocked attack, amendment, limit card, contracts with a revoked and a superseded contract, trace panel open (animations settled before each scan) | 1 finding family, fixed below |
| Keyboard | Tab through the first 40 stops at both widths, checking that every focused element shows an outline or ring | 0 without a visible focus |
| Target size (WCAG 2.2, 2.5.8) | Measured every visible control; probed the hit area of the two small text buttons with `elementFromPoint` | 2 controls under 24 px, kept (below) |
| Reduced motion | The existing `npm run screenshots` run with `prefers-reduced-motion: reduce`: no running animation at any step, including the new tour, status line and limit card | Pass |
| Overflow | The same run at 380 px: no horizontal overflow at any step | Pass |
| Text contrast of the design tokens | `test/ui-contrast.test.ts` computes the WCAG ratio for every text and surface token pair the design uses | All 12 pairs at 4.5:1 or more |

## Findings

### Fixed

**1. Past contracts failed text contrast (WCAG 1.4.3, serious).** A contract that is revoked, superseded or expired was dimmed with `opacity: .78` on the whole card, which pulled its text to 3.2 to 4.4:1 (the hash, the spend legend, the term labels, the chips and the "Download audit" link): 36 axe nodes. The card is now quieter by its background (`--paper`) and a dimmed meter (a graphic, not text), with no opacity on text. After the change axe reports 0 violations on all 10 states at both widths. `test/ui-contrast.test.ts` fails if opacity comes back on those cards.

### Kept on purpose (nothing here blocks)

| Finding | Why it stays |
| --- | --- |
| "Hide" (28x19 px) and "Reset demo" (73x19 px) are text buttons under 24 px | Their hit area is extended by a pseudo-element: a click 8 px above, below, left or right still lands on the button, so the effective target is well over 24 px. Making them bigger would change the layout |
| Literal colours (about 56 hex values, mostly white and shadows) outside the `:root` tokens in the stylesheets | Maintainability only, no user-visible effect; moving them is a wide edit with a visual-regression risk. A follow-up if the palette changes |
| A middle dot joins some meta strings (hash, status, amount; the "stopped by" list) | It reads clearly in this product UI and is not decoration; changing it would be a copy edit |
| The disabled "Send" button is low-contrast grey | Disabled controls are exempt from the contrast rule, and the grey is the standard signal that it is not available yet |
| Visual identity (tokens, type, cards, badges) | Unchanged: nothing in the audit forced a change |

## Reproduce

```bash
npm run build && npm run screenshots      # keyless demo flow, reduced motion, 380 px overflow, no console errors
npx vitest run test/ui-contrast.test.ts   # token contrast and the past-contract rule
```

The axe-core scan is not part of the repository (it would add a dependency); to repeat it, load `axe-core` into a Playwright page at each state above and run `axe.run` with the tags listed.
